# Remote - SSH for Kiro

Open a folder on a remote Linux host over SSH, so that the editor, the integrated
terminal, workspace extensions and the Kiro agent all run on that host.

Kiro publishes a remote extension host but no extension that connects to one.
This is the client half.

## Status

Working and verified on a real host: the remote server installs and starts, the remote
extension host connects, and the agent runs there. Signing in happens once per host —
this extension does not carry your sign-in across, and
[docs/DESIGN.md](docs/DESIGN.md) says why. See [docs/DESIGN.md](docs/DESIGN.md) for what is
built and what is deliberately not, and [docs/SECURITY_AUDIT.md](docs/SECURITY_AUDIT.md)
for the audit of existing options that decided the design.

## Requirements

- An OpenSSH client, 8.4 or newer, on your `PATH`. No other SSH client is
  supported, and none is bundled.
- A remote host running Linux on x64 or arm64 with glibc. Kiro publishes no
  remote server for macOS, and the published server is not a musl build.
- The `resolvers` API proposal enabled for this extension. Add
  `"enable-proposed-api": ["littlemex.kiro-remote-ssh"]` to `argv.json` and
  restart.

## How it connects

All SSH work is done by your own `ssh`, which means your `known_hosts`, your
keys and agent, and your `ProxyCommand` or `ProxyJump` all apply unchanged. A
host reachable only through a bastion needs no configuration here.

Everything for one host is multiplexed onto a single SSH connection, so you
authenticate once. The channel to the remote extension host is a byte stream over that
connection rather than a forwarded local port, so this extension opens no listening
socket on your machine for it. Where a listener is unavoidable — a remote extension
asking for a URL your browser can open — this extension holds the socket itself rather
than asking `ssh` to, so the kernel closes it when the editor ends, however it ends.

Hosts from your `~/.ssh/config` appear in the Remote Explorer, and there is an entry in
the remote indicator in the status bar.

## Supply chain

`npm run verify` checks the claims this project would otherwise be asking you to take
on trust: no runtime dependencies, no hardcoded network endpoints, no telemetry, no
install-time scripts, and a published archive containing exactly the expected files.
CI runs the same checks, publishes a CycloneDX bill of materials generated by a
dependency-free script in this repository, asserts that the bundle is byte-reproducible
from source, and attaches a signed provenance statement. See
[SECURITY.md](SECURITY.md).

```
npm install
npm run package
kiro --install-extension kiro-remote-ssh-0.1.0.vsix
```
